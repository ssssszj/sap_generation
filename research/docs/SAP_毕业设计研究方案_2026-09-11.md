# 面向临床试验统计分析计划生成的评测基准与小模型后训练研究

方案日期：2026-09-11。依据现有 `/Users/bytedance/school/sap_generation` 项目的代码、知识库、输入输出文件清单，以及文末所链接的公开资料整理。

本方案中的 SAP 指 Statistical Analysis Plan，即临床试验统计分析计划。默认周期 16 周；GPU、可用独立研究数量和统计专家参与时间尚未确认，以下数据规模、训练参数和效果目标均为计划值，不是已有实验结果。本次检查没有执行模型生成，也没有对历史生成稿做质量排名。

**1．推荐课题与研究主线**

推荐题目：**《面向临床试验统计分析计划生成的证据约束评测基准与小模型后训练方法研究》**。

核心问题：在总参数量低于 35B、可在内网运行的条件下，能否通过证据约束的结构化生成与针对统计错误的后训练，提高 SAP 的事实准确性、方法完整性和跨章节一致性，同时减少人工修改与反复调用模型的成本？

毕业设计交付三件相互支撑的成果：一个可复现的 benchmark、一套有对照实验的后训练方法、一个可私有化部署的演示系统。建议工作量分配为数据及评价 40%、模型及实验 40%、系统及论文整理 20%。比例可按资源调整，前端开发不作为主要研究投入。

推荐把论文贡献写成：

- 数据贡献：带原文证据、适用条件、错误类型和研究级划分的 SAP 生成与诊断评测集。
- 方法贡献：利用结构化事实与约束，将真实统计错误转成高质量偏好数据，进行任务 SFT 和定向 DPO。
- 实证贡献：分别测量工作流、后训练、修订轮数和量化的影响，给出小模型质量与部署成本的关系。

不把“使用 RAG”“使用 LoRA”“能生成 Word”单独当作算法创新。公开资料中已经存在 SAPAI 的分章节生成与专家评价工作，其摘要报告了 9 个试验、3 个模型和 27 份生成 SAP；作者也公开了复现实验提示词的配套项目。因此应重点突出评测设计、低参数模型后训练及错误减少，避免声称首次自动生成 SAP。[SAPAI 预印本摘要](https://www.medrxiv.org/content/10.64898/2026.03.19.26348626v2.full)、[作者配套项目](https://github.com/rct-sap-ai/sapai-open)。本次可读到摘要和项目资料，论文全文直连返回 403，尚未据其全文做系统复现。

这里有几项必须在正式实验前处理的问题：

1. **不能把输出文件数当作样本数。** 当前文件清单不能证明已有多研究语料；多个模型对同一个方案的输出，仍属于同一独立研究。先按研究号、方案标题和版本关系建立清单。
2. **眼科规则尚未通用化。** DOF、第二术眼、BCDVA/DCIVA 等应放入眼科扩展字段。现有 G2 对器械研究分析集前提的固定要求不能直接当作所有器械试验的普遍标准；应按具体方案证据和专家审核规则判断。
3. **rubric 存在明确的计数差异。** JSON 声明内容准确性 64 项、80 分，解析结果为 61 项、78 分；其余两维为 12 分和 8 分，解析权重合计 98。需要回到原表逐项核对，不能悄悄归一化后继续使用。
4. **当前的“规则”不等于独立评测器。** 把 rubric 注入提示词做修订，不代表已经实现可重复的自动评分。生成端的 QA 和最终 benchmark evaluator 应分开。
5. **长输入按字符截断。** 事实抽取只取 Protocol 前 45,000 字符和 CRF 前 25,000 字符；其他阶段还会截取更短正文或前文末尾。需要测量关键证据是否被截掉，并改为按章节检索和 token 预算组织上下文。
6. **事实抽取解析失败可能退化。** `extractSapFacts` 在 JSON 解析失败时返回 null；正式实验应记录抽取失败、有限重试和失败状态，不把缺少事实约束的输出混同正常运行。
7. **修订成本已经很高。** 带修订路径通常包括草稿 1 次、rubric 修订 1 次、5 个闸门各 1 次，即每章约 7 次调用，尚未包含事实抽取和额外修复。末尾仍有问题也可能返回正文，不能把“流程完成”视为“通过检查”。
8. **私有化接口还需要适配。** LLM 地址写死为 OpenRouter，并通过 HTTPS 请求；没有 API Key 时会回退占位输出。正式本地模式应支持本地地址和协议，并禁止占位响应进入实验结果。

建议先保存当前版本标识、提示词、输入哈希和历史输出，用于 legacy baseline；所有新实验采用单独版本的通用规则。

**3．任务范围：先让评测问题可回答**

第一版以常规干预性临床试验为主，优先平行组设计。选择连续型终点、二分类终点，以及有明确非劣/优效假设的研究；复杂平台试验、自适应设计和全套统计程序生成作为扩展。眼科作为已有优势子集，但整个任务不应被单一眼科模板定义。

核心输出是可审阅的 SAP 草稿，重点覆盖：研究设计与目标、终点及估计目标、分析集、主要和次要终点方法、缺失数据及敏感性分析、多重性、数据派生和访视窗、安全性分析、跨章节统一口径。封面、目录和一般格式以模板处理。

设置三个互相区分的输入场景：

| 场景 | 模型可见输入 | 评测重点 |
|---|---|---|
| 主赛道：Protocol → SAP | 研究方案、允许的通用指南 | 公开数据覆盖、完整生成能力 |
| 增强赛道：Protocol＋CRF → SAP | 方案和空白/注释 CRF | 变量、采集时间、派生规则；只在同一 CRF 子集内做有无 CRF 配对比较 |
| 辅助赛道：已确认决策 → SAP | 以上资料及固定的人工作出决策 | 实际使用中确认后的执行能力、修改时间 |

主赛道不依赖专家提前填好的事实表或从目标 SAP 抽取的核心内容。辅助赛道必须记录人工提供了哪些信息、花费多少时间，并与全自动结果分表报告。

参考 SAP 的每一项内容需区分四种状态：

- `explicit`：输入明确给出，例如样本量、主要终点时间点、单侧显著性水平。
- `derivable`：依据输入和固定推导规则能够确定，例如明确单位下的等价换算；必须保存推导依据。
- `proposed`：有多种可接受选择，需要在明确假设下提出方法建议。
- `needs_confirmation`：输入不足，无法把某种选择写成已经确定的试验事实。

例如，参考 SAP 写了软件版本或随机种子，而 Protocol 未写，不能因为模型没有猜中就判错。主分析方法若未确定，应给出具体确认问题和有条件的候选方案，不能凭默认模板定稿。同样，整篇都写“需要确认”也不能拿高分，必须同时评估已有信息覆盖率和合理补全能力。

Protocol 与 CRF 冲突时按字段记录来源，不简单认定“后出现的文字优先”。方法学以方案及有效修订为主要依据，CRF反映采集结构；无法消解的差异需显式保留。人工确认若修改方案口径，要记录为有来源的决策/变更，不能静默覆盖。

**4．Benchmark 数据建设**

优先从 ClinicalTrials.gov 的公开研究文档定位 Protocol 和 SAP 配对资料。官方文档体系包含独立 SAP，也包含 Protocol 与 SAP 的合并文件；因此必须检查内容，不能只依据文件名分类。[ClinicalTrials.gov 文档定义](https://clinicaltrials.gov/policy/results-definitions)、[数据 API](https://clinicaltrials.gov/data-api/about-api)。公开可读取不自动意味着可以重分发全部文件，应逐来源记录使用条件；必要时发布研究 ID、原始链接、处理脚本和允许公开的标注。

具体流程：

1. 收集候选研究元数据和文档链接，不读取结果数据来补全生成输入。
2. 按研究 ID 对齐文档，核对正式标题、版本、日期、修订关系和研究人群。
3. 保留原文件、文件哈希、抓取时间、解析版本及页码/段落映射。
4. 排除错配、缺关键页、只有摘要、解析无法恢复的文档，记录排除原因。
5. 优先纳入独立 Protocol＋独立 SAP。合并文件若含完整目标 SAP，先排除出主赛道；若确需纳入，人工划定并移除目标内容，保留正常 Protocol 自带的统计章节，并单列这类样本。
6. 对无法由对应 Protocol 支持的 SAP 新增决策逐条标记，必要时寻找匹配修订版本；不能把“文件来自同一 NCT”当作版本一致的充分条件。
7. 按疾病、研究阶段、设计、终点类型、语言、文档长度和来源模板统计分布。

推荐规模分两档：

| 项目 | 最小可交付版 | 推荐版 |
|---|---:|---:|
| 独立研究总数 | 60 | 120 |
| 训练 / 开发 / 最终测试 | 35 / 10 / 15 | 70 / 20 / 30 |
| 开发及测试金标准 | 25 个研究的关键字段与章节标准 | 50 个研究的关键字段与章节标准 |
| SFT 实例 | 800–1,500 | 2,000–4,000 |
| 偏好对 | 300–800 | 1,000–2,000 |
| 主要训练模型 | 一个 8–9B 模型 | 9B 主模型，27B 验证主要结论 |

实例数是从训练研究拆出的事实抽取、章节生成、纠错等任务数量，不能宣传为几千个独立临床试验。扩增倍数设上限，按研究均衡采样，避免单一方案支配训练。前两周先做 10–15 个研究的先导集，再决定是否扩至推荐规模。

推荐版测试集可分为 20 个同分布研究和 10 个来自预留疾病领域的研究，预留领域不进入训练和调参。先导案例只进训练/开发；不能先反复调试再纳入最终测试。若领域样本不足，改为来源模板/申办方留出，并如实标记，不把小子集外推成所有临床研究泛化。

划分以**研究及研究家族**为单位：同一研究的所有版本、SAP 章节、CRF、翻译稿、合成变体和偏好对必须在同一侧；再做全文及章节近重复检查。去掉研究编号做对照只能辅助检查记忆，不能证明不存在预训练污染。公开旧文档可能已进入基础模型训练，需在论文局限中说明，并优先增加未公开的授权外部测试或新文档留出。

英文公开数据与中文私有材料分开报告。英文翻译成中文不能被计为新的独立研究，也不能代替真实中文外部测试。建议主实验先做英文输入英文输出，中文作为独立扩展；系统同时支持中文展示。

**5．金标准、评价指标和评分器**

标注对象不只是“参考全文”，而是“本研究要求满足什么、证据在哪里、哪些写法可接受”。每条至少包括：研究 ID、检查项 ID、适用条件、字段值/可接受集合、来源和版本、证据页码/段落、证据原文、状态、严重程度、允许的方法替代、标注者及仲裁记录。

通用规则以 SAP 内容指南和 ICH E9/E9(R1) 为依据，再由统计专家转成可操作的检查项。E9(R1) 的估计目标框架适合补全当前事实表，记录研究人群、治疗条件、变量/终点、伴发事件处理及总体层面的汇总度量；不同年代研究不能因没有采用某个术语而直接判为错误。[SAP 内容指南](https://jamanetwork.com/journals/jama/fullarticle/2666509)、[ICH E9(R1) 正式指南](https://database.ich.org/sites/default/files/E9-R1_Step4_Guideline_2019_1203.pdf)。

将当前眼科检查项拆成三层：通用统计规则、领域规则、本研究事实约束。每条都有适用条件，未出现眼科终点的试验不检查第二术眼；适用性由输入及金标准确定，不能由生成文本决定，否则漏写内容就能逃避评分。

建议主指标是**研究级关键项全部通过率**：一个研究所有适用关键要求均满足，且没有严重虚构/冲突，才算通过。关键要求应同时包含正确性和必要覆盖，重大遗漏也记为失败。该指标与每研究的严重错误数、关键事实准确率、必要内容覆盖率共同报告，避免全或无指标过粗。

| 指标 | 定义与实现 |
|---|---|
| 关键事实准确率及召回率 | 在预先列出的终点、分析集、样本量、α、时间窗等字段上核对；数值、单位和方向优先规则计算 |
| 无依据陈述率 | 没有输入、合法推导或明确建议标识支持的实质性声明占比；同时报告声明总数与覆盖率 |
| 跨章节冲突 | 对同一实体/字段的各章节断言做冲突检查；报告每份文档冲突数和无冲突率 |
| 方法充分性 | 专家或校准后的评审器评估模型、协变量、假设、估计与检验、缺失策略和敏感性分析是否可执行 |
| 证据正确率与覆盖率 | 引用片段是否存在、是否支持断言、应有证据的断言是否已引用；真实页码但不支持内容仍失败 |
| 信息不足处理 | 是否识别需确认事项，是否错误拒绝已有明确证据的事项，候选建议是否标明条件 |
| 人工效用 | 关键章节修订时间、重大修改数、盲审偏好及可审阅性 |
| 运行成本 | 全文时延、输入输出 token、模型调用数、GPU 峰值显存、失败率 |

辅助总分可暂设为事实正确 30%、方法充分 30%、一致性 20%、不足信息处理 15%、表达与结构 5%。这组权重是初始设计，应在开发集和专家校准后冻结。各维度先在适用项内计算，再按预设权重汇总；某维度无适用项时使用预先规定的重分配规则。既报告总分，也单报严重错误，不能让格式分抵消主终点错误。

评分实现分为三类：

1. 确定性核验：数值、单位、区间、日期、标识、结构合法性、来源存在性。公式和不等号必须先明确比较差的定义，不能只按关键词匹配。
2. 结构化语义评审：给独立评审模型必要证据、候选段落和检查项，让其输出通过/失败/无法判断、证据与理由。无法判断交仲裁；不得默认为通过。报告仲裁前无法判断比例。
3. 人工金标准：开发/测试关键项由两名标注者独立评分并仲裁，优先确保关键统计项由有统计背景的人审定。若资源只允许一名专家，第二名可做训练后的初评，论文需如实披露，不声称双统计专家一致性。

人工预算先用 3–5 个案例实测。粗估推荐版 50 个开发/测试研究、每名标注者每研究 1–2 小时，双人即 100–200 小时，另加仲裁及训练样本抽查；若实际更慢，减少非核心章节或采用最小版。完整全文质量和关键章节质量分开评价，不把只读过关键章节的审核标成全文金标准。

在 100–200 个分层抽样的章节/检查项上校准评审器，包含少见严重错误和相近方法替代。报告与人工的混淆矩阵、错误类型召回、评分一致性；相关系数高不等于严重错误识别好。训练偏好评分器与最终盲测评分器分版本、冻结检查模板；最终保留人工抽检，防止只学会迎合评分器。

最终测试以研究为聚类单位计算差值和 bootstrap 置信区间，同一研究的多章、多次采样不当作独立样本。主比较和主指标提前确定；测试集仅在方案冻结后正式运行。15–30 个测试研究的领域分析和显著性结论应保持克制。

**6．生成方法：带证据的结构化中间表示**

推荐流程：

`原始文档 → 保留位置的解析 → 章节/表格索引 → 证据检索 → 事实与决策表 → 章节计划 → 分章生成 → 约束检查 → 有针对性的修复 → 全文审计 → 导出草稿`

中间表示建议命名为 `SAP-IR`，它是可追踪的事实、决策和一致性状态，不一定要上图数据库。JSON 与少量关系检查即可实现：

```json
{
  "study_id": "study_demo",
  "schema_version": "1.0",
  "facts": [{
    "field": "primary_endpoint.timepoint",
    "value": "Week 24",
    "status": "explicit",
    "evidence": [{"doc_id": "protocol_v2", "page": 18, "span_id": "p18_s4"}]
  }],
  "decisions": [{
    "field": "primary_analysis.missing_strategy",
    "value": null,
    "status": "needs_confirmation",
    "question": "主分析缺失数据策略及对应假设是什么？"
  }],
  "constraints": [{
    "field": "primary_endpoint.timepoint",
    "scope": ["endpoint_definition", "primary_analysis", "visit_window"]
  }]
}
```

上述值是格式示例，不来自用户研究。实际 schema 应覆盖研究设计、每个终点、每个估计目标、分析集、比较定义、检验方向、α 分配、多重性、缺失策略、访视窗和派生规则；领域特有内容放扩展字段。

检索从简单可控方案开始：当前研究内按章节标题、术语和 BM25 检索，必要时再增加本地向量检索及重排；通用指南使用独立索引。主方案不检索历史测试 SAP，也不把目标 SAP 放进向量库。先测证据 Recall@K；证据找不到时优先解决解析和检索，不能仅靠增加后训练掩盖输入缺失。

每章上下文包含相关原文证据、已确认事实、适用规则和已生成文档的结构化状态。只保留前文末尾容易丢掉最早的关键定义，应以全局字段状态约束跨章一致性。

输出正文与审阅信息分开保存：正文保持专业文档形式，侧边记录来源、建议、冲突和确认状态。规则检查优先定位需要修复的段落，最多 1–2 轮；修复后必须重查受影响字段以及是否引入新错误。未解决的关键问题随草稿保留，并阻止状态被标为“已通过”。

这个设计产生一个可检验假设：显式证据及统一字段状态能降低事实和跨章错误。它也可能传播错误抽取，因此需要“人工正确 IR”对照估计上限；该对照明确标为 oracle，不与真实自动生成结果混报。

**7．后训练路线：任务 SFT → 错误定向 DPO**

优先选择已经具备通用指令能力的开放权重模型，再做领域适配。默认不做从零预训练，也不把大规模继续预训练列为必做；现有指南体量不足以支撑这类主线。

阶段一：构造多任务 SFT 数据。

| 任务 | 输入 → 目标 | 建议初始占比 |
|---|---|---:|
| 事实及证据抽取 | 原文片段 → 合法 JSON、证据定位和状态 | 25% |
| 章节生成 | 证据＋IR＋章节要求 → 经审核的章节 | 40% |
| 错误诊断及修复 | 候选段落＋证据 → 错误类型和最小修复 | 20% |
| 不足与冲突处理 | 缺失/冲突输入 → 具体确认事项和有条件建议 | 15% |

比例只是起点，按开发集薄弱项调整。参考 SAP 不应原样全部当标签：先处理无法由输入确定的内容，保留可证实的章节文本，对新增方法选择补充决策输入或标为建议。SFT 只对目标输出计算监督损失；保存证据和简短理由即可，不必采集冗长自由推理过程。

训练标签来源按可信度分层：真实 SAP 经审核的可支持部分、专家修订、规则验证的教师生成；每类记录来源和质量状态。教师模型只处理公开或明确获准可外发的数据。默认私有试验材料的解析、标注辅助、推理均留在内网；未授权时不调用外部教师服务。

阶段二：构造错误定向偏好对。

先用训练集研究运行基线和 SFT 模型，保留自然错误，再有控制地注入错误扩充薄弱项。优先涵盖：

- 主要终点或时间窗错误。
- 比较差的定义与 H0/H1 方向不一致。
- 分析集纳入/剔除条件错误。
- 主分析与敏感性分析缺失策略混淆。
- 单侧/双侧和显著性水平不一致。
- 多重性调整遗漏或与输入冲突。
- 跨章节同一字段出现两种口径。
- 编造输入未确定的方法、数值或证据。
- 在信息充分时错误拒答，或重复通用套话而遗漏要求。

每个 pair 的输入完全相同，chosen 和 rejected 尽量接近长度、术语和结构，仅存在可解释的质量差异。修复之后重新验证，不能假设“后一次修订必然更好”。两边都有重大缺陷或优劣有争议时弃用/仲裁。

偏好优先级建议：严重错误和重大遗漏 → 输入忠实与证据支持 → 方法完整及一致性 → 可读性。不要让篇幅长或“写得像参考文档”压过统计正确性。

推荐先做标准 DPO，通过数据构造体现方法差异，不自行发明复杂损失。DPO 使用同一输入下的优选/劣选输出，相对固定参考模型优化偏好，无需另训显式奖励模型；可用 TRL 实现。[DPO 原论文](https://arxiv.org/abs/2305.18290)、[TRL DPO 文档](https://huggingface.co/docs/trl/main/en/dpo_trainer)。

必须设置两个对照：普通质量偏好 DPO，以及只把 chosen 样本追加做 SFT。尽量匹配研究来源、样本量和训练 token 预算。这样才能回答：收益来自错误定向数据、偏好学习方式，还是仅仅多看了一批好答案？

训练建议起点：

| 项目 | SFT | DPO |
|---|---|---|
| 微调方法 | LoRA/QLoRA | 从 SFT checkpoint 出发的 LoRA/QLoRA |
| LoRA rank | 16 或 32 起步，最多追加一个对照 | 与 SFT 方案保持清晰一致 |
| 学习率试点范围 | 2e-5～1e-4 | 5e-7～5e-6 |
| 训练轮数 | 1～2，依据开发集早停 | 1 起步 |
| 序列预算 | 4k–8k 先跑通，必要时扩至 16k | 章节/局部修订级，不直接偏好整篇 SAP |
| 选择标准 | 关键错误、覆盖率、证据与失败率 | 关键错误减少且覆盖率不退化 |

这些是小规模试点参数，不是经过本任务验证的最优配置。锁定模型 revision、tokenizer、聊天模板、推理模式、软件版本、随机种子及数据哈希。QLoRA 是在量化底座上进行低秩适配的已有节省显存方法，但实际资源还受激活、序列长度等影响。[QLoRA 原论文](https://arxiv.org/abs/2305.14314)。

不把 GRPO/PPO 作为默认必做。只有 SFT/DPO 已经完成、奖励经过人工校准且算力充足时，才在可验证局部任务上增加一个强化学习扩展实验；不要把不可靠的全文总分直接当唯一奖励。

**8．模型与算力选择**

按照“总参数低于 35B”理解需求，包含部署所需全部模块，不按 MoE 激活参数钻空子。已有文件名中的 35B-A3B 不能因激活参数约 3B 就视为严格低于 35B；默认不纳入满足约束的候选，保留为历史对照即可。最终用实际模型配置和加载参数复核边界。

推荐只做两级主模型：

| 候选 | 定位 | 选择理由 |
|---|---|---|
| Qwen3.5-9B | 主训练与全部方法消融 | 降低迭代成本，验证小模型是否确实受益 |
| Qwen3.5-27B | 主要结论复验、质量较高的部署候选 | 在约束范围内比较更大模型收益 |
| Qwen3-32B | 可选成熟文本模型对照/兼容性回退 | 官方卡标注总参数 32.8B，仍低于 35B |

官方资料可核实这些模型的规模与开放权重；Qwen3.5 的候选含视觉编码器，本任务先用文本路径，检查训练和服务框架对具体架构的支持，不为多模态额外扩大任务。不能用通用榜单预先断言哪个 SAP 效果最好。[9B 模型卡](https://huggingface.co/Qwen/Qwen3.5-9B)、[27B 模型卡](https://huggingface.co/Qwen/Qwen3.5-27B)、[32B 模型卡](https://huggingface.co/Qwen/Qwen3-32B)。

按十进制 GB 估算，P 个参数的 BF16 权重约为 2P 字节，4bit 权重理论裸值约为 P/2 字节。因此 9B 约 18/4.5 GB，27B 约 54/13.5 GB，32.8B 约 65.6/16.4 GB。这些只是参数权重下界，未包括额外模块、量化元数据、缓存、临时张量、激活和训练状态。

| 可用资源 | 建议决策 |
|---|---|
| 单卡 24GB | 以 9B 量化推理和短上下文 QLoRA 试点为主；DPO/长上下文先做显存试跑，不能保证全部配置可用 |
| 单卡 48GB | 优先把 9B SFT/DPO 做完整；27B 量化推理，27B 训练视短序列试点决定 |
| 单卡 80GB | 9B 完整实验和 27B LoRA/QLoRA 试点；DPO 长序列仍须实测 |
| 双卡 80GB | 可将 27B 训练、较长输入和关键结果复验纳入计划，仍不默认全参数训练 |

先在目标 GPU 上跑 20–50 个代表性 batch，记录真实吞吐、峰值显存和失败情况，然后按总处理 token 推算预算。不要在尚未知硬件时承诺“某卡几小时训练完”。例如 3,000 个实例平均 4,000 token、训练 2 轮，名义 SFT 处理量约 2,400 万 token；DPO 还要计算 chosen/rejected 和参考前向，需单独测量。

**9．实验设计：区分模型能力和额外推理预算**

先在 9B 上跑主实验，27B 只重复基线、SFT 和最终方法，避免模型数量消耗数据审核预算。

| 编号 | 模型/方法 | 要回答的问题 |
|---|---|---|
| L0 | 当前项目原始工作流 | 已有基础是什么水平、耗费多少调用 |
| B0 | 未做本任务训练的模型，直接生成 | 简单基线 |
| B1 | 同模型＋统一证据/IR 工作流 | 结构化工作流的贡献 |
| B2 | 任务 SFT＋同 B1 工作流 | SFT 的贡献 |
| B3 | SFT＋普通偏好 DPO＋同工作流 | 一般偏好优化的收益 |
| B4 | SFT＋错误定向 DPO＋同工作流 | 主要方法结果 |
| B5 | SFT＋仅 chosen 追加 SFT＋同工作流 | 增益是否仅来自新增好样本 |
| C0 | 强外部模型＋固定工作流，公开子集 | 外部参考水平，不能称为理论上限 |

B1–B5 使用完全相同的检索器、证据预算、IR 定义、章节模板、修复上限和最终评分器。先固定工作流比较训练方法；另设系统预算实验比较“无修订/1 轮修订/原多轮修订”，报告达到某质量水平所需的 token 和延迟。强外部模型只在符合数据边界的子集上比较，不能把不同测试集分数直接放一起排名。

优先消融四项：移除证据约束；移除全局一致性状态；定向偏好换成普通偏好；只用合成错误换成自然错误与合成错误混合。资源充足再加 oracle IR 和对训练研究数量的学习曲线。

鲁棒性另设挑战集：删除关键方法信息、加入冲突版本条款、等价单位表达、关键证据放在长文后部、CRF 缺失和解析噪声。挑战变体全部继承原研究划分，单独报告，不冒充更多独立研究。

关键训练对比尽量重复 2–3 个种子；若成本不允许，先对 9B 做重复、27B 做一次复验并说明限制。最终生成固定解码设置；选择少量研究重复生成观察稳定性，推理 token 也计入成本。

建议提前冻结的研究目标，而非承诺结果：B4 相对 B2 的严重错误率相对下降 20%–30%，同时覆盖率下降不超过预设容忍量；人工关键章节修订时间下降约 20%；最终部署模型相对未量化版本质量损失不超过开发阶段确定的界限。若原错误率已经很低，应调整关注绝对改善和置信区间，不追逐夸大的相对百分比。

即使 DPO 未显著优于 SFT，只要评价可信、对照充分、误差分析清楚，仍可形成完整毕业设计；如实解释偏好噪声、任务上限或成本收益，不以测试集调参制造正结果。

**10．私有化部署与现有工程改造**

保留现有 Next.js 前端和 API，新增独立的 Python 研究与推理周边模块。推理服务优先用经过具体模型兼容性验证的 vLLM 或 SGLang；官方 Qwen 模型卡给出了本地兼容接口示例。[本地服务示例](https://huggingface.co/Qwen/Qwen3.5-27B)。

建议部署边界：浏览器 → 现有应用服务 → 任务队列/生成编排 → 本地文档解析、检索、模型推理、检查器 → 本地文件与结果存储。长文档通过异步任务、进度和断点重试处理，避免一次请求超时后整篇重生成。

优先改造清单：

- LLM client 增加可配置 provider/base URL/model/超时，支持本地 HTTP 或部署要求的 HTTPS；内网模式不隐式回退云端。
- PDF/DOCX 解析保留页码或稳定段落 ID，检测表格、公式、乱码和扫描页；OCR 只在需要时启用本地组件。
- facts 使用严格 schema 校验，抽取失败成为显式状态；对关键缺失项执行有限重试和人工确认。
- 将规则和评分从长提示词中拆成版本化组件，按领域和本研究启用。
- 持久化每次运行的模型、权重/adapter、量化格式、输入哈希、规则版本、证据、token、调用链和未解决问题。
- 实现草稿/待确认/检查失败/可提交人工审核状态，正文与审阅报告同时导出。
- 加入登录权限、研究隔离和日志脱敏；预下载模型与依赖后做断网验收，确保解析、检索、embedding、推理和日志链路没有外部依赖。

部署验收至少包含：文档输入输出全链路断网运行；相同输入可复现配置；失败可定位到章节；关键证据可点击查看；量化前后跑同一套关键检查；在规定输入长度和并发 1/2 的负载下记录全文耗时及显存。延迟目标先以 pilot 实测后制定，不以单个 token/s 代替端到端性能。

研究目录建议与业务代码分开，避免训练与评测逻辑塞进 TypeScript 生成器：

```text
sap_generation/
  app/                       现有界面与 API
  lib/                       业务生成编排、导出
  knowledge_bank/            版本化通用规则与领域扩展
  research/
    data_manifest/           研究清单、来源、哈希、划分
    schemas/                 事实、证据、决策、检查项格式
    data_pipeline/           解析、对齐、去重、清洗
    annotation/              标注指南与仲裁记录
    benchmark/               独立评测器、运行配置
    training/                SFT、偏好构造、DPO
    experiments/             固定配置、汇总表、错误分析
  deploy/                    内网部署配置与验收说明
```

原始私有文件和生成内容放受控存储，不因为新增 research 目录就提交到 Git。能公开时交付元数据、脚本、schema、非敏感标注和可发布 adapter；不能公开的部分提供复现实验说明及清晰的数据可用性声明。

**11．16 周里程碑**

| 周次 | 重点 | 必须得到的可检查产物 |
|---|---|---|
| 1–2 | 现有案例盘点、相关工作、10–15 个研究先导集、GPU 试跑 | 研究清单、错因分类、首版标注规范、资源实测 |
| 3–4 | 扩展采集、版本核对、冻结划分、通用/领域 rubric | 数据卡 v0.1、训练/开发/测试清单、评分器初版 |
| 5–6 | 独立评价校准、统一证据与 IR 工作流、基线 | 基线报告、评分器人工一致性报告、主要瓶颈 |
| 7–8 | 清洗标签、多任务 SFT、开发集迭代 | 可复现 SFT checkpoint、数据统计、第一次错误对比 |
| 9–10 | 自然错误采样、偏好构造、DPO 及 chosen-SFT 对照 | 偏好数据卡、主方法和对照结果 |
| 11–12 | 方法冻结、关键消融、最终测试、可选 27B 复验 | 主结果表、置信区间、鲁棒性与外部子集结果 |
| 13–14 | 量化部署、人工修订时间试验、断网验收 | 部署包、审阅报告、性能和效用结果 |
| 15–16 | 论文、图表、演示、复现整理 | 论文定稿、演示视频、数据与模型说明、答辩材料 |

论文写作从第 3 周开始记录方法与实验协议，不留到最后两周重建全过程。

阶段决策点：

- 第 2 周没有足够成对资料：先缩到 Protocol → 核心章节，不等待 CRF 三件套。
- 第 4 周独立研究不足 30：限定领域、采用研究级交叉验证或小型留出，定位为原型验证；不能宣称通用 benchmark。
- 第 6 周评分器不能可靠识别严重错误：扩大人工关键项评测，暂缓自动偏好构造。
- 第 8 周 SFT 变差：先检查标签是否含不可推断细节、领域偏差和输入截断，再增加训练。
- 第 10 周偏好对质量不足：保留 SFT、偏好数据分析和有限 DPO 对照，优先确保论文实证完整。
- 算力不足：保留 9B 全套实验，27B 只做推理对照；先取消复杂 RL、多模态、全 TFL/SAS 代码生成。

**12．开题、论文和答辩如何组织**

开题陈述可以写为：本研究面向临床试验 SAP 的长文档生成场景，研究小参数语言模型在事实忠实性、统计决策完整性及跨章节一致性方面的不足；构建具有原文证据、适用规则和研究级隔离的评测基准，设计基于结构化证据和错误定向偏好数据的后训练流程，并在私有化原型系统中验证质量与成本。

论文内容顺序建议：问题与相关工作；任务定义与数据集；评测与标注可靠性；结构化生成及后训练；实验与错误分析；部署和人工效用；局限。相关工作必须对比 SAPAI 等已有流程，不能仅综述通用大模型和 LoRA。

答辩优先准备六类图表：数据筛选及划分流程；错误类型分布；基线/SFT/DPO 主结果；证据与一致性消融；质量—推理成本关系；量化与私有化端到端性能。关键案例展示同一段原文、模型错误、修复后内容和判定证据，选择规则提前确定，避免只挑最漂亮的样例。

最终验收应检查是否交付：可审计的研究数据清单、冻结的划分和评分器、人工标注一致性结果、训练数据来源及偏好理由、模型与 adapter 标识、基线和消融结果、失败案例、离线部署与量化验证，以及论文和复现说明。

**13．现在最值得先做的两周工作**

第一步，把已有人工晶状体案例做透：识别正确版本的 Protocol/CRF/参考 SAP，列出 30–50 条有证据的关键要求，从已有多模型生成稿抽取真实错误；对全部历史生成稿不必立刻做全文精评。

第二步，补 10–15 个独立公开研究，让规则经历领域和设计差异；检查现有眼科规则是否错误触发，确认 SAP 配对、解析和金标准的人工成本。

第三步，实现离线批量运行和逐项结果导出，固定现有基线与新通用基线；在小模型上完成一次 SFT 的训练—推理—评分闭环。

两周后应能够用数据回答：独立样本能扩到多少，专家能标到什么程度，主要瓶颈是证据遗漏、领域知识、统计推理还是一致性，哪一级模型能在现有硬件运行。再据此冻结最终规模，避免先承诺大规模训练、最后发现数据和评测无法支撑。
